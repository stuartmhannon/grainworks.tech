② Gateway & Transport

How your message gets normalized, authenticated, and handed to the brain. Click any box for details.

Transport Adapters ▶
Each LLM provider has its own wire protocol. Transport adapters normalize them all into one internal format.
  • Anthropic Messages API: Claude-specific message format, role types, caching headers
  • OpenAI Chat Completions: the default — used by DeepSeek, OpenRouter, most providers
  • Bedrock Converse: AWS Bedrock's native format (boto3-based)
  • Gemini: Google's generativeai format
  • Codex: Anthropic's Codex format for terminal-native coding sessions
  • Vertex AI: Google Cloud Vertex endpoint format
  • Each adapter: translates system prompts, tool schemas, streaming, tool results
  • Each adapter: normalizes error responses into Hermes' error classification system
Approval Control Protocol (ACP) ▶
Every operation goes through ACP — approve, deny, or defer. Smart defaults for known-safe operations.
  • ACP registration: each tool/operation registers with the ACP system
  • Approval modes: auto (let known-safe through), prompt (ask user), deny (block)
  • Smart deny: when a known-safer alternative exists, suggest it instead
  • Scope: per-operation overrides (e.g. "always approve file reads from ~/Projects")
  • ACP adapters: acp_adapter/ directory with provider-specific implementations
  • ACP registry: acp_registry/ directory for operation registration
  • Context-aware: destructive command detected → stricter approval
  • Session-scoped: approval preferences persist within a session
Credentials & Secrets ▶
API keys, tokens, passwords — handled securely through credential pools and secret sources.
  • Credential pool: manages per-provider API keys with automatic rotation
  • OAuth token refresh: auto-refreshes expired tokens on 401 responses
  • Secret sources: 1Password CLI, Bitwarden CLI, environment variables, macOS Keychain
  • Touch ID gate: ~/.hermes/secrets/keys.env protected by biometric auth
  • credential_persistence.py: saves and restores credentials across restarts
  • credential_sources.py: abstracts multiple credential backends
  • Rate limit tracking: cross-session rate limit status (Nous Portal)
Provider Model Resolution ▶
Which model gets called and in what order — primary, fallback chains, tool-specific overrides.
  • Primary: configured provider + model in config.yaml (model.default, model.provider)
  • Fallback chain: fallback_providers list — tried in order when primary fails
  • Model-specific fallback: per-cron-job model overrides
  • Tool overrides: delegation tasks can pin specific models
  • Local inference: Ollama with mistral-nemo:latest as local fallback
  • Dynamic resolution: cron jobs inherit from provider defaults, not hardcoded names
  • Context window enforcement: 64K minimum — checks before sending the request
