Tool System Overview ▶
How tools are defined, registered, loaded, and called. Every turn the model sees available tools as JSON schemas in the system prompt.
  • Each tool is a Python file in tools/ with: schema (JSON-Style), handler function, input validation
  • Tools loaded per-turn based on toolset configuration (hermes-cli, web, delegation, etc.)
  • Schema includes: name, description, parameter types, required fields, enum constraints
  • Registry: tools/registry.py manages discovery and loading
  • Tool middleware: _apply_tool_request_middleware — hooks into every tool call
  • Concurrent dispatch: up to 8 parallel workers (execute_tool_calls_concurrent)
  • Sequential dispatch: one at a time for ordered operations
  • Budget config: token budget per tool call, scaled to model's context window

MCP Server Gateway
MCP Integration ▶
Model Context Protocol — external tools connected via stdio or HTTP SSE. Registered in config.yaml under mcp_servers.
  • mcp_tool.py: core MCP tool integration — routes tool calls to MCP servers
  • mcp_stdio_watchdog.py: monitors stdio-based MCP servers, restarts on crash
  • mcp_oauth.py / mcp_oauth_manager.py: OAuth flow for MCP servers
  • managed_tool_gateway.py: tool gateway for managed MCP connections
  • Two transport modes: stdio (subprocess) and SSE (HTTP, persistent connection)
  • Config: mcp_servers section in config.yaml with command, args, env, URL
  • Discovery timeout: 1.5s for MCP server handshake

Guardrails & Safety
Tool Guardrails ▶
Before and after every tool call: security, budget, idempotency checks.
  • before_call(): check tool name + arguments against threat patterns
  • Destructive command detection: rm -rf, sudo, docker rm -f, dd, etc.
  • after_call(): classify result as success, failure, or error
  • Idempotency: same tool + same arguments + same result → skip mid-execution
  • Budget tracking: per-tool token/iteration counts, scaled to context window
  • Halt decision: if guardrail blocks execution, synthesize "tool denied" result
  • Recovery hints: on repeated tool failures, suggest alternative approaches
