Input Surfaces [full detail]
How I hear you — CLI, Desktop, Web UI, API Server, Platform Channels, Computer Use
▶
CLI / TUI
Terminal REPL via prompt_toolkit
  • Fixed input area, history, key bindings
  • Local machine only — no network needed
  • Full tool access (hermes-cli toolset)
Desktop App
Electron + React, native OS integration
  • Tauri/Electron shell on macOS, Windows, Linux
  • cua-driver for Computer Use (desktop automation)
  • Inline diffs, file mutation verifier
Web UI
Browser-based — Vite + React + TypeScript
  • Zero install, accessed via browser or Hermex mobile
  • Streaming responses, session management
  • Mobile-friendly companion app (Hermex)
API Server
OpenAI-compatible HTTP endpoint
  • /v1/chat/completions — drop-in replacement for any OpenAI client
  • Header-based auth (api key)
  • Lets external tools hook into Hermes
Platform Channels
Telegram · Discord · Slack · Signal · WhatsApp · SMS
  • Each platform has its own adapter plugin
  • Supports DMs, group chats, threads
  • Channel-specific toolset (platform_toolsets)
Computer Use
cua-driver — drive the desktop in the background
  • Background mode: doesn't steal cursor or focus
  • Click, type, scroll, drag via AX tree + screenshots
  • Works on any window (hidden, minimized, behind others)

The Brain — Turn Cycle [interactive deep-dive]
The core: build context → call LLM → execute tools → loop
▶
A. Build Context
Assemble messages + tools + memory
  • Sanitize & repair message history
  • Inject memory/plugin context
  • Apply prompt caching
  • Normalize for KV cache reuse
B. Pre-Flight
Budget · Interrupt · Context pressure
  • Iteration budget check
  • Interrupt signal check
  • Compress if near context limit
  • Ollama window too small? hard stop
C. Call the LLM
DeepSeek · Claude · Ollama · etc.
  • Streaming or non-streaming
  • Retry with exponential backoff
  • Fallback provider on exhaustion
  • Content filter detection
D. Execute Tools
Guardrails · sequential or concurrent
  • Destructive command detection
  • Up to 8 parallel workers
  • Failure classification
  • Compress → loop back
E. Finalize
Return answer or handle edge cases
  • Normal delivery · empty-response nudge · thinking-only recovery
  • Truncated tool-call retry · partial stream recovery
  • Persist to session DB · clean up resources

Tools & MCP [full detail]
55+ built-in tools + external MCP server ecosystem
▶
Built-in Tools (55+)
File ops, terminal, browser, web, vision, memory, cron, and more
  • Core: terminal, file, web_search, browser, vision, memory
  • Agent: delegate_task, clarify, cronjob, kanban, code_execution
  • Media: image_generation, tts, video_generation, transcription
  • Platform: send_message, Discord, Home Assistant, X search
  • Meta: session_search, skills_manager, todo, blueprints
  • Each tool has: schema, input validation, result formatting
MCP Gateway
Model Context Protocol — stdio & HTTP SSE servers
  • mcp_tool.py: MCP tool integration
  • mcp_stdio_watchdog.py: restart crashed stdio servers
  • mcp_oauth.py: OAuth for MCP servers
  • Connects to: Graindrop, Josh.ai, UnRAID, Obsidian, LinkedIn,
  • Sonarr, Radarr, Porkbun, MyAnonamouse, StatBar, Chipotle
Guardrails & Safety
Destructive command detection, idempotency, budget
  • Before each tool call: check by name + arguments
  • Destructive patterns: rm, sudo, docker rm -f, etc.
  • Idempotency: same tool + args + result? skip execution
  • Budget: track token/iteration usage per call
  • Safe harbor: define non-sensitive fallback actions

Skills & Plugins [full detail]
Procedural memory that loads when relevant; modular extensions
▶
Skills System
Instructions + pitfalls + reference files — loaded by relevance
  • ~55 skills covering: engineering, devops, productivity, creative, research, integrations
  • Skill preprocessing: relevance matching against current task
  • Skills HUB: community skill marketplace
  • Self-improving: patched when I find gaps during use
  • Provenance tracking: author, version, license metadata
  • Lazy loading: only the relevant ones enter the prompt
Plugin System
Memory backends, model providers, platform channels, observability
  • Memory: Holographic (SQLite+FTS5+HRR), Honcho, Mem0, and more
  • Model providers: configurable connection to any LLM API
  • Platform channels: Telegram, Discord, Slack, Signal, WhatsApp
  • Context engine: manages compression, checkpointing
  • Observability: usage tracking, billing, credits
  • Security: guidance plugin for threat detection

Persistence & State [full detail]
Everything that survives between sessions
▶
Fact Store (Holographic)
946 facts · entity resolution · trust scoring · compositional reasoning
  • SQLite-backed with FTS5 full-text search
  • Entity resolution: same person/thing across names
  • Trust scoring: facts rated helpful/unhelpful train accuracy
  • HRR vectors for semantic retrieval
  • Memory banks for context-aware recall
Session Archive
FTS5-searchable conversation history
  • sessions.db: every message from every session
  • session_search tool: keyword, phrase, boolean queries
  • Response store: persisted tool results
  • Cross-session recall: "what did we do about X?"
State & Config
Persistent agent state, config YAML, secrets
  • state.db: environment, usage data, session tracking
  • config.yaml: model config, provider setup, tool preferences
  • Secrets: 1Password, Bitwarden, Touch ID-gated env files
  • Checkpoints: snapshot/rollback for disaster recovery

Background Systems [full detail]
Cron scheduler · Kanban · Gateway daemon · Curator — run without me
▶
Cron Scheduler
15,000+ concurrent job types
  • Time-based and interval-based scheduling
  • no_agent mode: script-only, zero LLM cost
  • agent mode: full reasoning with tool access
  • Email screening, expense reminders, morning briefing, book extraction
Kanban System
Multi-profile worker dispatch
  • Separate profile processes with isolated toolsets
  • Worker log rotation, failure limits, stale timeout
  • Auto-decompose large tasks into sub-items
Gateway Daemon
Webhook listener · cron ticker · background housekeeping
  • Listens on port 8644 for incoming webhooks
  • Graindrop voice memo → processed, webhook fires, I respond
  • Josh.ai scene trigger → Hermes action
  • launchd-managed, auto-restarts on crash
Curator
Self-audit · memory cleanup · skill maintenance
  • Runs nightly at 2 AM
  • Audits: memory consistency, skill staleness, config drift
  • Backs up agent state to Tower
  • Prunes stale checkpoints and orphaned data
