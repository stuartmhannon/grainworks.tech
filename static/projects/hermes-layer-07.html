Scheduling & Automation
Cron Scheduler ▶
15,000+ concurrent job types. Two modes: no_agent (script-only, zero LLM cost) and agent (full reasoning with tools). Gateway daemon must be running for cron to fire.
  • cron/scheduler.py: core scheduler — manages job lifecycle, tick dispatch, persistence
  • cron/scheduler_provider.py: provider abstraction for different scheduling backends
  • cron/lifecycle_guard.py: prevents runaway jobs, enforces timeouts
  • cron/blueprint_catalog.py: reusable job blueprint library
  • cron/suggestion_catalog.py: suggests cron jobs based on usage patterns
  • Script mode (no_agent=True): pure script execution, no LLM token cost — ideal for watchdogs
  • Agent mode: full reasoning with tool access — for tasks needing judgment
  • Skills attachment: cron jobs can load specific skills before running
  • Per-job model override: pin specific providers/models per cron
  • Context chaining: job A's output feeds into job B via context_from
  • Workdir: per-job working directory with project context files
  • Attach to session: continuable jobs create threads for follow-up replies

Kanban System ▶
Multi-profile worker dispatch — distributes tasks across isolated profiles with their own toolsets and models.
  • config: kanban section in config.yaml (dispatch_interval, failure_limit, worker_log_rotate)
  • Orchestrator profile option: tasks sent to a coordinating profile
  • Auto-decompose: large tasks split into sub-items configurable per tick
  • Isolated per worker: each kanban worker gets a fresh profile with its own tools
  • Worker logs: rotated at 2MB, 1 backup kept
  • Failure handling: configurable failure limit before task is abandoned
  • Stale timeout: 4h timeout for stalled workers
Daemon Services
Gateway Daemon ▶
Background process managed by launchd. Runs cron scheduler + webhook listener. Must be running for cron jobs to fire.
  • launchd service: ai.hermes.gateway plist at ~/Library/LaunchAgents/
  • KeepAlive=true: auto-restarts on crash
  • RunAtLoad=true: starts on user login
  • 60s ticker: scheduler checks every 60 seconds for pending jobs
  • Webhook listener: port 8644, receives POST requests from external systems
  • Webhook subscriptions: Graindrop (voice memo → Hermes), Josh.ai (scene trigger)
  • webhook_subscriptions.json: persisted subscription registry
  • Dispatch in gateway: cron and kanban can dispatch directly from the gateway process
Webhook Subscriptions ▶
External systems can trigger Hermes via webhooks — voice memos, Josh scenes, and more.
  • graindrop — fires when a voice memo is transcribed; delivers to origin (this chat)
  • josh-trigger — fires when a Josh.ai scene calls the relay; runs with Josh + ideas-reservoir skills
  • Platform: webhook.enabled=true in config.yaml, listens on 0.0.0.0:8644
  • HMAC signing: webhook payloads signed with configurable secret
  • delivery targets: origin (current chat), local (save to file), or specific platform:chat_id
iMessage Bridge ▶
Background Python HTTP server that wraps imsg CLI, enabling cross-user iMessage send/receive.
  • imsg_bridge.py: Python HTTP server on 127.0.0.1:8646
  • Runs as the hermes macOS user (UID 502), signed into Messages.app
  • Endpoints: /health, /chats, /history/:chat_id, /send
  • Polling cron (every 2m, no_agent) checks for new incoming messages
  • Auto-responder: reads new messages via Hermes API, responds via bridge
  • Launchd-managed: AI.hermes.imsg-bridge plist for auto-start
  • Requires: Full Disk Access + Automation (Messages) granted to the hermes user
Self-Maintenance
Curator ▶
Autonomous self-audit that runs nightly. Checks memory consistency, skill staleness, config drift, and backup state.
  • curator.py: main curator logic — runs at 02:00 daily via cron
  • curator_backup.py: handles state backup to Tower (rsync-over-SSH to /mnt/user/Backups/hermes/)
  • Audits: memory (orphaned facts, low-trust entries), skills (stale references, provenance drift), config (model/provider mismatches)
  • Backup: config.yaml, state.db, sessions.db, secrets vault → Tower
  • Prunes: stale checkpoints, orphaned response data, expired cache
  • Reports: audit findings saved to ~/.hermes/reviews/
Loop Closure ▶
Weekly proactive self-review across 7 axes: model config, cron health, skills, fact store, tool quirks, edge cases, upgrade candidates.
  • Weekly Sunday 10PM cron
  • Model audit: verify model.default, cron model overrides, delegation model
  • Cron health: check all jobs for recent failures, stale entries
  • Skills audit: verify YAML frontmatter, missing author fields, orphaned references
  • Fact store: check for stale/contradictory facts
  • Tool quirks: capture any tool-specific workarounds discovered that week
  • Edge cases: note any failure modes hit during the week
  • Upgrade candidates: identify config or workflow improvements
