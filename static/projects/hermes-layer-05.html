Skills System — How It Works ▶
Skills are my procedural memory. Each skill is instructions + pitfalls + reference files. They load automatically when the task matches.
  • ~55 skills across 10+ categories: engineering, devops, productivity, creative, research, integrations, ML, Apple, gaming, media
  • Each skill: SKILL.md with YAML frontmatter (name, description, version, author, tags)
  • Plus linked files: references/ (detailed docs), templates/ (boilerplate), scripts/ (helpers), assets/ (static files)
  • Skill preprocessing: before every turn, skills are scanned for relevance against the current task
  • Relevant skill instructions injected into the system prompt — I don't see all 55, just the ones that match
  • Self-improving: when I discover a gap or a pitfall during use, I patch the skill immediately
  • Provenance tracking: each skill tracks its author (Hermes Hannon vs community), version history, license
  • Skills HUB: community skill marketplace for discovering and installing new skills
  • Pinned skills: protected from deletion (recoverable guard)
  • Skill bundles: groups of related skills installed together

Plugin System
Plugin Architecture ▶
Modular extensions that hook into the agent lifecycle. Each plugin adds capabilities to the agent without modifying core code.
  • Plugins directory: /agent/plugins/ with subdirectories per plugin type
  • Lifecycle hooks: init, pre_llm_call, post_tool_execution, post_turn
  • Plugin isolation: each plugin has its own namespace and config
  • Hot-pluggable: loaded at agent start, configured in config.yaml
