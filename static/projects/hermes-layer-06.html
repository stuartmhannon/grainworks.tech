⑥ Persistence & State

Everything that survives between sessions — memory, conversation history, config, secrets. Click any box for details.

Active Memory (Holographic)
How Holographic Memory Works ▶
The active memory provider — local-only SQLite with FTS5 full-text search, HRR vectors, entity resolution, and trust scoring.
  • 946 stored facts across categories: user_pref, project, tool, general
  • SQLite-backed: single local file at ~/.hermes/memory_store.db
  • FTS5 full-text search: keyword queries across all facts
  • HRR (Holographic Reduced Representation) vectors: 1024-dim compositional retrieval
  • Entity resolution: recognizes the same person/thing across different surface forms
  • Trust scoring: each fact has a score (0.0–1.0), trained by fact_feedback (helpful/unhelpful)
  • Memory banks: named collections for context-aware recall (e.g. "engineering", "personal")
  • Auto-extraction: when enabled, facts are automatically extracted from conversation
  • Actions: add, search, probe (all facts about an entity), related (what connects to it), reason (compositional across entities), contradict (find conflicting claims)
Memory Lifecycle ▶
How memory enters, persists, and gets cleaned up — from capture to curation.
  • Explicit save: memory tool called to store user preferences, corrections, decisions
  • Automatic extraction: fact_store auto-extract enabled (configurable)
  • Curator pruning: nightly curator pass clears stale/low-trust facts
  • Trust training: fact_feedback marks facts helpful or unhelpful, scores adjust
  • Consolidation: related facts merged by entity resolution
  • Minimum trust filter: facts below 0.3 are excluded from queries by default
  • User profile: dedicated store for who the user is (name, role, preferences, style)
Session History
Session Archive ▶
Every conversation is saved to a searchable SQLite database. The session_search tool lets me find anything from any past session.
  • sessions.db: SQLite database at ~/.hermes/sessions.db
  • FTS5-backed: full-text search across all messages from all sessions
  • session_search tool: 4 query modes — discovery (FTS5 search), scroll (around a message), read (full session), browse (recent sessions)
  • Bookend display: when searching, shows first 3 + last 3 messages of matching sessions (goal → resolution)
  • Context window: ±5 messages around the match for understanding context
  • Cross-session recall: "find the session where we discussed X" works
  • Role filtering: search user messages, assistant messages, or tool output
Response Store & Checkpoints ▶
Tool results are persisted for reference, and snapshots enable rollback.
  • response_store.db: persisted tool results for cross-session reference
  • Verification evidence: tool outputs stored for audit trail
  • Checkpoints: state snapshots at configurable intervals (default: every 24h)
  • Max snapshots: 20, with auto-prune of oldest
  • Auto-rollback: on crash or bad state, can restore from last checkpoint
  • Retention: 7 days, delete orphans on prune
Config & Secrets
State & Configuration ▶
Persistent agent state across restarts — environment, usage data, session tracking.
  • state.db: agent state — session IDs, environment variables, usage counters
  • config.yaml: user configuration — model, providers, toolsets, agent settings, platforms
  • write-protected: config.yaml is write-protected from patch/write_file — must use "hermes config set"
  • provider_models_cache.json: cached model lists from provider discovery
  • auth.json / auth.lock: session auth state for platforms
  • usage-data: per-session and cumulative token/API usage tracking
Secrets & Credentials ▶
API keys, tokens, passwords — kept secure via Touch ID-gated vault and external credential services.
  • keys.env: Touch ID-gated environment file at ~/.hermes/secrets/keys.env
  • Protected by: `security authorize -u -P -l "system.login.touchid"`
  • Secrets alias: view, copy, edit, path operations
  • SECRETS_FILE: path set in .zshrc for all Hermes processes
  • Bitwarden integration: hermes-pass encrypted vault at ~/.hermes-pass/vault.json.age (730 items)
  • 1Password integration: secret_sources/ plugin for 1Password CLI
  • credential_persistence.py: saves/restores credentials across restarts
  • credential_pool.py: manages per-provider credential pools with auto-rotation
