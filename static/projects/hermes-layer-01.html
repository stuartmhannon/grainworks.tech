① Input Surfaces

How I hear you — six ways a message can reach me. Click any box for details.

CLI / TUI ▶
Terminal-based REPL via prompt_toolkit. The original interface — full power, zero abstraction.
  • Fixed input area: multi-line text editor at the bottom of the terminal
  • File history: persistent ~/.hermes/history across sessions
  • Keyboard shortcuts: Ctrl+Enter to submit, Tab for autocomplete, arrow keys for history
  • Inline diffs: shows file changes directly in the terminal output
  • Kawaii spinner: animated thinking indicator while the model works
  • Slash commands: /skill, /memory, /todo, /debug, /cost, /reset
  • Personality switching: /personality concise, /personality pirate, etc.
  • Output paging: persistent output buffer (last 200 lines shown)
  • Full hermes-cli toolset: all 55+ tools available
  • Multi-line paste detection: auto-formats pasted code blocks
Desktop App ▶
Native desktop application — Electron shell with React frontend. Installed via Hermes Desktop.
  • Cross-platform: macOS, Windows, Linux (Electron + React + TypeScript)
  • Standalone window: dedicated app, not a browser tab
  • In-app update: "Update Now" rebuilds both Python backend and Electron shell
  • cua-driver integration: Computer Use tool drives the desktop in background mode
  • Desktop-specific build pipeline: apps/desktop/ with electron/ directory
  • Build: hermes desktop --build-only compiles the Electron bundle
  • In-app settings: "Keep Follow Ups in Chat" toggle, appearance preferences
  • Bootstrap repair: auto-recovers from boot loops after update
Web UI ▶
Browser-based interface — Vite + React + TypeScript. Accessed via desktop browser or mobile.
  • Zero install: works in any modern browser
  • Streaming responses: SSE-based real-time text delivery
  • Session management: resume from any device
  • Suggested follow-up questions: inline suggestions after each response
  • Markdown rendering: headings, code blocks, tables, LaTeX, Mermaid diagrams
  • Media previews: MEDIA:/path renders images, audio, video, PDFs inline
  • Workspace indicator: [Workspace::v1: /path] tag on every message
  • Model picker: switch providers per-session (overrides config.yaml default)
  • Mobile companion: Hermex app connects to the same WebUI backend
  • Profile selection: switch between multiple Hermes profiles
API Server ▶
OpenAI-compatible HTTP endpoint — lets any tool talk to Hermes as if it were OpenAI.
  • Endpoint: /v1/chat/completions — drop-in replacement for OpenAI SDK
  • Authentication: API key in header (configurable)
  • Streaming: SSE-based response streaming
  • Tool integration: supports OpenAI function-calling format
  • Open WebUI connects here: web-ui.camel-hoki.ts.net → Hermes API
  • Hermes Mobile (Hermex) connects here
  • Exposed via Tailscale Serve: hermes.camel-hoki.ts.net/api
  • Multi-turn: maintains conversation state across API calls
Platform Channels ▶
Messaging platforms — Telegram, Discord, Slack, Signal, WhatsApp, SMS. Each has its own adapter plugin.
  • Each platform = separate plugin with its own toolset (platform_toolsets)
  • Platform-specific tools injected: e.g. Discord has channel/message/reaction tools
  • Supports DMs, group chats, and threaded conversations
  • Plugin architecture: platforms/ directory in the agent source
  • Toolset filtering: only relevant tools loaded per platform
  • Each platform adapter handles: auth, message format, rate limiting, reconnection
Computer Use ▶
cua-driver — drive the desktop in the background. Click, type, scroll, drag without stealing focus.
  • Background mode: actions don't steal cursor or keyboard focus
  • SOM mode: screenshots with numbered overlays on every interactable element
  • AX tree: accessibility tree for reliable element targeting
  • Click by element index (preferred) or pixel coordinates (fallback)
  • Works on hidden/minimized/behind windows — doesn't need focus
  • Supported input: click, type, key combos, scroll, drag, set_value
  • App-specific capture: limit to one app's window for less noise
  • Safety blocks: no clicking permission dialogs, password prompts, payment UI
  • Fixed overlays: cua-driver's agent cursor is a visual cue for the user; real OS cursor stays put
  • Requires: Accessibility + Screen Recording permissions granted to cua-driver
  • Backend: cua-driver v0.5.2+ (installed via brew or GitHub release)
